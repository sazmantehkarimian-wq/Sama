# Requirement Traceability Rules

Every approved requirement must be traceable through:

Requirement ID → Rule ID → Design/Architecture → Implementation → Test ID → Evidence → Release status

## Rules

- Never mark a requirement implemented without evidence.
- Ambiguous requirements are BLOCKED, not guessed.
- Version 1.0 changes require Change Request approval.
- One implementation may satisfy multiple requirements; record all links.
- One requirement may require multiple tests.
- Failed tests keep the requirement from being release-ready.
