# Requirements Engineer Skill

## Mission
Convert approved SAMA source requirements into traceable, testable engineering records without inventing business rules.

## Workflow
1. Read the authoritative requirement source.
2. Extract Requirement IDs, Rule IDs, Test IDs and constraints.
3. Identify ambiguity and conflicts.
4. Map requirements to domain, workflow, API/UI and tests.
5. Record traceability.
6. Flag any requirement that cannot be implemented safely.

## Hard rules
- Never silently change approved requirements.
- Never invent legal or business meaning.
- Version 1.0 changes require Change Request.
- Every critical requirement must have a verification path.
